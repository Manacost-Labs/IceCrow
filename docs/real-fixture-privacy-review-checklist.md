# Real fixture privacy review checklist

Human review gate for promoting an anonymized capture candidate into
`tests/fixtures/battlegrounds/`. Automated scans reduce risk; only a human
review authorizes a commit. This checklist contains no private values.

## Where the candidate lives

Candidates are generated by `FixtureTool import` into a private directory
outside the repository (by convention
`%LocalAppData%\IceCrow\fixture-candidates\<name>\`) and consist of
`recording.icecrow.json`, `expected.json`, and `README.md`. A machine-made
review package (`review-package.md` next to the candidate) summarizes the
automated scan results for the reviewer.

## What to inspect

Open all three candidate files and verify each point:

1. **BattleTags** — search for `#` followed by digits. There must be none;
   the anonymizer replaces player names deterministically.
2. **Nicknames / real names** — skim every `entityName` value. Names must be
   anonymized placeholders, not recognizable player or account handles.
3. **Account identifiers** — search for `gameAccountId` values; they must be
   anonymized tokens, never `hi=`/`lo=` values from the original log.
4. **Absolute paths / machine names** — search for `:\`, `Users`, and your
   Windows user name. There must be none.
5. **Free text** — `unknownPower` events carry raw log text; the anonymizer
   strips them, so `content` fields must be absent or sanitized. Any other
   free-text field must contain only game vocabulary.
6. **Non-ASCII residue** — Cyrillic or other localized minion names are
   game content, but localized *player* names are private; when in doubt,
   reject and re-anonymize.
7. **Manifest truth** — `expected.json` must declare
   `"sourceType": "real-anonymized"`, a reason, the recording format
   version, and checkpoints that actually exist in the recording.
8. **Golden validation** — `FixtureTool validate --fixture <candidate>` must
   pass at review time, not only at import time.

## Recording the decision

- Approval must be explicit: reply or record `APPROVED FOR COMMIT` naming
  the candidate. Only then may the candidate be copied into
  `tests/fixtures/battlegrounds/` and committed in its own commit, after
  which the privacy guard tests and the golden corpus must run green.
- Anything less than explicit approval keeps the honest status:
  `REAL FIXTURE CANDIDATE READY · HUMAN PRIVACY REVIEW REQUIRED · NOT
  COMMITTED`.
- If any check fails, fix the anonymizer or regenerate the candidate;
  never hand-edit a candidate to pass review.
